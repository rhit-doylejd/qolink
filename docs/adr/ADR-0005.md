# ADR-0005: Fixed-Size Frame with TX Delay Field

## Status

Proposed. Supersedes ADR-0002 and amends ADR-0003 if accepted.

## Context

The ADR-0002 frame carries 18 B of overhead around a variable 1..1024 B payload.
Several of those fields are redundant on a point-to-point link:

- The preamble lets a receiver lock to the bit clock after the medium goes silent.
  That matters on a shared medium; a point-to-point link can stay locked
  permanently with continuous Manchester idle.
- The SFD and EFD are Manchester code violations, which are line-coding symbols
  rather than frame bytes.
- The EFD and the length field both mark the end of a frame.
- The 8 B absolute timestamp only exists to compute a time difference, and it
  requires both ends to share a counter epoch.

Variable frame sizes also complicate credits (byte counts), buffer sizing, and the
latency bound, whose blocking term is the largest lower-class frame.

## Decision

**Line coding layer.** The line carries continuous Manchester idle between frames.
Each frame is preceded by a start symbol one byte time long, made of a defined
pattern of Manchester code violations, generated by the encoder. There is no
preamble and no EFD. A start symbol received mid-frame aborts the current frame.

**Frame format.** Every frame is 40 bytes:

| Field    | Size   | Contents                                                   |
|----------|--------|------------------------------------------------------------|
| Header   | 1 B    | Class (2b), Sequence (6b)                                  |
| TX Delay | 3 B    | T2 − T1 in counter ticks, saturating                       |
| Payload  | 32 B   | Fixed size; shorter messages are padded                    |
| FCS      | 4 B    | CRC-32 over Header, TX Delay and Payload                   |

Class: `00` Low, `01` Medium, `10` High, `11` Control (credits and round-trip echo).
Sequence is counted per class, modulo 64.

**Credits.** Credits are counted in frames: one credit is one frame, which is one
receive buffer slot.

**FIFOs.** Each FIFO entry holds one frame's payload. Depth is counted in frames.

**Latency measurement.** T1, T3 and T4 keep their ADR-0003 meanings. T2 is
redefined as the cycle the line encoder accepts the start symbol from the framer.
The framer computes TX Delay = T2 − T1 and sends it in the frame instead of T1.
The receiver computes:

```
latency = TX Delay + D_wire + (T4 − T3)
```

D_wire is the constant delay from T2 to T3 (TX pipeline, cable, RX pipeline). It is
measured at link startup with a round-trip echo frame, in which the echoing end
reports its own hold time in the reply's TX Delay field.

**Field sizes** (100 MHz counter, 4× oversampled Manchester, 12.5 Mbps, 640 ns
per byte):

- Class, 2 bits: three data classes plus one control class.
- Sequence, 6 bits: the sequence space must exceed the frames in flight per class,
  which the credit window caps at 16.
- TX Delay, 24 bits: 10 ns ticks span 168 ms. Worst-case low-priority queueing is
  about 1.1 ms with high and medium traffic capped at 50% of the link (16-frame
  FIFO, 4-frame burst) and under 3 ms at an 80% cap, so the field has at least 60×
  margin. Header and TX Delay together form one 32-bit word.
- Payload, 32 bytes: one frame is 41 byte times on the line including the start
  symbol, so τ = 26.24 µs and line efficiency is 78%. A 64 B payload would gain
  about 8% efficiency and nearly double τ. 32 B is eight 32-bit words.
- FCS, 32 bits: CRC-32 is already implemented and verified.

## Consequences

- Overhead drops from 18 B to 8 B per frame (9 byte times on the line).
- No length field or EFD logic. The receiver counts 40 bytes after each start symbol.
- Credits, buffer sizing and the latency bound are all expressed in whole frames.
- The frame carries no absolute time, so the two counters do not need a shared epoch.
- Halving the round-trip time assumes both directions have equal delay. The B→A
  path adds clock-recovery pipeline stages, so the known pipeline difference must
  be subtracted and the residual stated as measurement uncertainty.
- TX Delay saturates only if a frame waits more than 168 ms, which requires a
  receiver that stops returning credits or traffic beyond the utilization cap. A
  saturated value indicates one of those conditions, not a link fault.
- Messages longer than 32 B must be fragmented by the driver. Messages
  shorter than 32 B are padded; how the valid length is conveyed is left to the
  driver layer.
- The framer loses its preamble, sequence, EFD and length logic, and its 6 B
  timestamp state becomes a 3 B TX Delay state. CRC and FIFO modules are unchanged.
- Revisit if the link moves to an Ethernet PHY whose MAC interface (RMII) requires
  preamble and SFD bytes.
