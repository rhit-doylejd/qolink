# ADR-0002: Framing Format

## Status

Proposed

## Context

Frames must separate packets on the wire and carry each packet's class and length.

## Decision

| Field     | Size        | Contents                                              |
|-----------|-------------|-------------------------------------------------------|
| Preamble  | 1 B         | 0x55, after continuous Manchester idle                |
| SFD       | 1 B         | Manchester code-violation pattern                     |
| Header    | 2 B         | Class (2b), Length (11b), reserved (3b)               |
| Sequence  | 1 B         | Per-class, mod 256                                    |
| Timestamp | 8 B         | TX counter value captured as the SFD is sent          |
| Payload   | 1..1024 B   | Capped per class                                      |
| FCS       | 4 B         | CRC-32 (IEEE 802.3) over Header, Sequence, Timestamp, Payload |
| EFD       | 1 B         | Code-violation pattern, distinct from SFD             |

Class: `00` Low, `01` Medium, `10` High, `11` Credit. A Credit frame's 3 B payload
holds the cumulative credits granted for each data class.

The receiver will:

1. End frames at the EFD, not by Length. A Length mismatch is an error.
2. Stage each frame and commit it to a class FIFO or credit counter only after the
   FCS and field checks pass.
3. Capture its own counter at the SFD and compute latency as RX timestamp minus the
   frame's TX timestamp.

## Consequences

- A corrupted header cannot desynchronize the link, and corrupted frames never reach
  buffers or credits.
- The RX hardware computes latency per frame, so live latency is available for the
  statistics counters and the demo without off-board matching.
- The timestamp is only valid if both counters share a time base. This requires the
  sync-pair reference clock in the time-base ADR.
- Overhead is 18 B per frame. The timestamp and CRC-32 add 10 B to every frame,
  including small high-priority ones, which widens the latency bound.
- CRC-32 gives stronger error detection than CRC-16 on short frames.
- Revisit if the line code changes to 8b/10b or the time-base decision drops the
  sync pair.
